Agent Blackbox · docs

Every action your AI agent takes is checked before it runs.

Blackbox sits between your agent and the world. When the agent is about to run a command, open a file, install a package, fetch a page or call a model, Blackbox looks at that one action first and decides: block it, flag it for you, or let it through. It runs on your machine, works offline, and never sends your commands or prompts anywhere.

How a check works

Each step below happens for every single action, in a fraction of a millisecond. Press a step to read what it does.

The four flows

Everything Blackbox does belongs to one of four flows. Two keep it informed, one protects you in the moment, and one remembers.

Block, flag or allow

What Blackbox does with a finding depends on two settings and one rule.

Mode

Audit records and shows every finding but stops nothing — good for getting to know what your agent does. Block stops serious findings before they run. You switch in Settings.

Severity

Each finding is low, medium, high or critical. In block mode, findings at or above your block level are stopped; the rest are flagged.

Trust

Only verified threats (from Umanitek's curated graph) and protections you switch on yourself, like Trader Shield, can block. Community reports and guesses only ever flag, so nobody else can stop your agent.

Blackbox fails open: if Blackbox itself ever has a problem, your agent keeps working. A security tool must never become the reason your work stops.

The threat graph

Blackbox's knowledge of known threats — malicious packages, wallet drainers, scam sites, dangerous commands — comes from a verified threat graph that Umanitek curates and publishes on the OriginTrail Decentralized Knowledge Graph (DKG). Your install runs its own small DKG node, which keeps a copy of that graph on your machine. Checks then ask your own node, never a server, so they are fast and private.

Verified graph

Curated by Umanitek. Only its curator can write to it. Its threats may block. blackbox status shows how many of its assets are on your machine.

Community graph

A separate graph where Blackbox users can share sightings — only if they choose to. Community findings only flag, never block.

Wallets protected

Trader Shield keeps your agent out of your crypto wallets: their key stores in browser profiles, desktop wallets' folders and command-line key files. Blackbox only checks that those folders exist; it never opens or reads them. Each wallet below is listed from the product's own wallet packs.

Browser support

A browser wallet is protected wherever its official version can be installed. Chrome, Brave, Edge, Opera, Vivaldi and Arc all install extensions from the Chrome Web Store, so a wallet installed from there is protected in all of them. Firefox and Edge also have stores of their own, where a wallet may or may not be published.

    What was tested

    Real-machine runs

    Tests on fresh machines, set up the way a real person would: real browsers, real wallets from the official stores, Blackbox from the one-line installer.

    Sources

    Where every claim on this page about a wallet comes from: the publisher's own download page or the store's own listing. Search results were not used as evidence; several led to copycat wallet sites.

      Privacy and sharing

      Stays on your machine

      Your commands, prompts, files and findings. Blackbox's logs are redacted: seed phrases, keys and other secrets are removed before anything is written.

      Leaves only if you say so

      Sharing a threat with the community graph is off until you turn it on. A shared report says which threat was seen and how severe it was — never your command or prompt text. Shield findings (wallets, secrets) are never shared. Turn sharing off any time with blackbox report --disable-sharing or the dashboard's switch.

      Install and services

      The one-line installer sets up Hermes (the agent framework), the Blackbox plugin, a DKG node and this dashboard, and protects the Hermes home it set up. If it finds other agents (Hermes profiles, OpenClaw workspaces) it lists them and asks first; each profile is its own trust boundary, so Blackbox never adds itself to one on its own.

      Starts at login

      On macOS the DKG node and the dashboard run as LaunchAgents. On Linux they run as systemd services; for a normal user the installer turns on "lingering" so they keep running after you log out and start at boot.

      Where things live

      Blackbox's records: ~/.hermes/blackbox/. The DKG node: agent-blackbox/.dkg/ next to the installed checkout. Settings: the Hermes config.yaml.

      Updating

      Run the same one-line installer again. It keeps your settings and services, and new wallets are offered to you rather than switched on behind your back.

      Commands

      Every command is blackbox <command> (the same as hermes blackbox <command>).

      statusSettings, whether the DKG node answers, the rules loaded and how many findings were logged.
      syncRefresh the threat rules from your DKG node now. --wait waits for the first full download.
      dashboardStart this dashboard at http://127.0.0.1:9700.
      attach / detachProtect the Hermes homes or OpenClaw workspaces you name (blackbox attach ~/.hermes/profiles/work), or every one found with --all; detach switches Blackbox off, and it stays off.
      reportShare a threat with the community graph, see what you shared, or turn sharing on or off.
      rulesLocal overrides: let one verified rule only flag on this machine, undo that, or list your overrides.
      setupFinish an install that came from the Hermes plugin catalog: DKG node, threat graphs, agents, dashboard.
      setup-llmSet up the optional second-opinion model that reviews possible prompt injections (advisory only).
      chatStart a Hermes chat in Blackbox's own profile.
      curateTools for community-graph curators.

      When something looks wrong

      "Node unreachable"

      The DKG node is not answering. Protection still works from the rules already on disk. Check its service (LaunchAgent on macOS, systemd on Linux), or re-run the installer.

      Few verified assets

      A fresh install downloads the verified graph in the background over about half an hour. blackbox status shows the count growing.

      A wallet is not listed

      Blackbox lists a wallet once its store exists on disk. Open the browser with the extension once, and make sure the wallet is ticked in Trader Shield's settings.

      Something was blocked that should not be

      The finding explains why. For a verified rule, blackbox rules can make it flag only on this machine.

      Glossary

      Agent
      An AI assistant that can take actions on your computer, such as running commands or editing files.
      Finding
      What Blackbox reports when an action matches a threat or a protection: what it saw, how serious it is, and what it did.
      Key store / vault
      The encrypted files where a wallet keeps your keys. Copied off your machine, a vault can be attacked offline.
      Seed phrase
      The 12 to 24 recovery words that are the wallet: whoever has them controls it.
      DKG
      OriginTrail's Decentralized Knowledge Graph, a shared network for verifiable data. Blackbox's threat graphs live on it.
      Shield
      An optional protection pack for one kind of risk, such as Trader Shield for crypto wallets.
